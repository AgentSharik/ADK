# ADK — Active Directory Kit · сводка для продолжения работы (на 2026-09-07)

## Что это
Наш проект: настольная утилита для администраторов домена — PyQt6 + ldap3 + pywin32 (Windows), SQLite/PostgreSQL.
Начинался как мой однофайловый монолит, после аудита переработан в пакет `adk/`. Продукт называется **ADK** (везде так; о прежнем имени — только слово «ребрендинг»).

## Что сделано в последней партии (3.3.0)
Меню «Питание ПК» вместо «Перезагрузить»+WoL (разбудить, заблокировать экран, выйти, сон, перезагрузить, выключить); роль «ПК» в карточке — только просмотр (кнопки AD-изменений скрыты, поля readonly, чекбоксы заморожены, группы без ±); карточка «Роль» на дашборде; сохранение пароля исправлено (DPAPI через ctypes без pywin32, причина отказа показывается, данные не стираются при сетевой ошибке, пароль подставляется); вкладка «Диагностика» в «Здоровье ПК» (заглушка); карта подсети — просветы между ячейками, легенда справа; окно входа не режет текст ошибки; окно «Новый пользователь» компактнее.

## Незакрытое
- **Полная переработка окна пинга** — ждём описание, каким его хочет видеть автор.
- «Сессии на ПК» (query user / msg / logoff) — **не делать**, зарезервировано за автором.

## Правила работы (обязательные)
1. Весь промежуточный текст и итоги — **по-русски**; итог — компактная сводка.
2. Никогда не упоминать AnyDesk (только RMS), Telegram/автообновление (удалены), QR-коды, «кэш» в интерфейсе.
3. Учётка: ровно два состояния бейджа «Активна / Не активна», без дублей в инспекторе. ФИО-колонка — только имена (в таблице «Фамилия И.О.», в инспекторе полностью), без логинов. Поиск — без телефонов (ПК, ФИО, IP; по IP находится и принтер — показать только его).
4. Колонки по умолчанию: Логин, ФИО, Учётка, Имя ПК, Сеть, Телефон, IP-тел; меню колонок — простой чек-лист. Таблицы: строки разделены, вертикальные линии, акцентная полоска у выбранной строки, ширина по тексту. Скроллбары заметные.
5. Здоровье ПК: карта диска — плитки объёмные, ничего не наезжает, таблицы справа, «Почистить» согласован с картой; сканирование только вручную.
6. Свободный IP: сверка с DHCP; цвет ячейки = статус, найденный — зелёный с рамкой.
7. Видео: реалистичная запись экрана без склеек/повторов, живые графики не «замерзают», каждое новое видео содержит всё из предыдущего + новое; показывать пинг офлайн и онлайн ПК и обе роли (AD/ПК). Правки по производству видео не упоминать.
8. README короткий (детали в `docs/*.md`), эмодзи в заголовках, скриншоты и GIF. Никаких реальных доменных имён/UNC в коде и доках.
9. Автор — новичок в тестах: объяснять без жаргона на примерах его кода.
10. Ничего нового не должно портить БД и CSV-файлы; живой опрос принтеров БД не меняет.

# Порядок работы над каждой партией правок (делать так же, как раньше)

## 1. Тесты — обязательны для каждой новой функции и каждого исправления
Стек: `pytest`, PyQt6 в режиме `QT_QPA_PLATFORM=offscreen`, LDAP подменён заглушкой (`tests/test_gui.py`: `FakeConn`, `FakeEntry`, `ENTRIES`, фикстуры `qapp`, `fake_conn`, помощники `_main(qapp, fake_conn, monkeypatch)` и `_wait(cond, app, ms)`). Импорт помощников в других модулях: `from tests.test_gui import ENTRIES, _main, _wait, fake_conn`.

Куда класть: `test_core.py` (чистая логика, БД), `test_gui.py` (главное окно), `test_accounts.py` (карточка, учётки, роли, вход), `test_fleet.py` (парк ПК, доступ), `test_health.py`, `test_ping.py`, `test_network.py` (свободный IP, DHCP), `test_tools.py`, `test_ui.py` (геометрия, темы), `test_learning.py` (учебные тесты для автора).

Как писать (стиль проекта):
- каждый тест начинается с docstring по-русски: **что проверяем и почему** («3.3.0: раньше … → теперь …»);
- один тест = один сценарий пользователя, с комментариями-шагами по-русски;
- внешнее (subprocess.Popen, netutils.subprocess.run, MessageBox.question, сеть) — через `monkeypatch`, ничего реального не запускать;
- роли переключать `access.set_rights(pc=…, ad=…)` и **обязательно возвращать** `access.reset()` в `finally`;
- окна не выше 800×600 (экран offscreen), после `show()` — `qapp.processEvents()`, при необходимости `layout().activate()`;
- если правишь поведение — сначала найти существующий тест на него и обновить, не удалять.

Проверка перед сдачей (все четыре, в этом порядке):
```
pyflakes adk tests docs/*.py                                  # должно быть пусто
QT_QPA_PLATFORM=offscreen pytest -v tests > docs/test-logs/pytest.txt   # именно -v, отчёт читает лог
for f in e2e_scenario e2e_round2 e2e_round3; do PYTHONPATH=/home/user QT_QPA_PLATFORM=offscreen python tests/$f.py | tail -n 1; done
python docs/make_report.py
```
Плюс визуальный смоук новых/изменённых окон: offscreen-скрипт, `apply_theme(...)` с `PRESET_THEMES["ocean"]`, `widget.grab().save(...)` и посмотреть картинку глазами (наезды, обрезанный текст, лишняя высота).

Автору объяснять тесты без жаргона, на примерах его же кода (он учится их писать).

## 2. Версия, CHANGELOG, README, FEATURES
- Поднять версию в `adk/__init__.py` (патч — правки, минор — заметные функции).
- `CHANGELOG.md`: новый блок сверху `## X.Y.Z — короткий заголовок партии`, подразделы **✨ Новое / 🐞 Исправлено / 🧪 Тесты** нумерованными пунктами; у исправлений писать **причину** («почему было так») и что стало; в конце — число тестов «N (+k): что покрыто».
- `README.md` держать коротким (~70 строк): обновить число тестов в блоке «🧪 Качество», добавить версию в одну строку «📜 История» (формат «3.3.0 — …;»). Подробности — только в `docs/FEATURES.md` (таблица возможностей: обновить/добавить строку с пометкой версии), `docs/INSTALL.md`, `docs/DEVELOPMENT.md` (число тестов).
- Заголовки README — с эмодзи; никаких реальных доменов/UNC; не упоминать видео, AnyDesk, прежнее имя, QR, Telegram.

## 3. Скриншоты и GIF
- Всё генерируется скриптом `docs/make_screenshots.py` (offscreen, тема «ocean», те же демо-данные, что в тестах) → PNG и GIF в `docs/`. Ручных скриншотов нет.
- Новое окно/вкладка → добавить в `make_screenshots.py` кадр `docs/<имя>.png` (имена по смыслу: `health_errors.png`, `user_card.png`, `free_ip.png`…), описать его в `docs/SCREENSHOTS.md`; если функция «живая» (анимация, ввод) — GIF `docs/demo_<тема>.gif`.
- В README — только 2–3 самых показательных картинки таблицей (`| ![...](docs/x.png) | ... |`), остальные — в `docs/SCREENSHOTS.md` / `docs/FEATURES.md`.
- После каждой партии перегенерировать: `QT_QPA_PLATFORM=offscreen python docs/make_screenshots.py` — чтобы картинки соответствовали версии.

## 4. Видео и его сценарии — ВНЕ проекта
