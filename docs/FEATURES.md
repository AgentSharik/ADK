# ✨ Возможности ADK — полный список

[← README](../README.md)

| Область | Что умеет |
|---|---|
| **Единый поиск** | Живой поиск (debounce 450 мс) по фамилии/имени, логину, почте, отделу, организации, должности, кабинету, **имени ПК и IP** в одной таблице. Телефоны намеренно не ищутся (шум на числовых запросах). IP-префикс сравнивается по октетам (`10.0.2` ≠ `10.0.20.x`); IP или имя ПК без пользователя в AD показывают сам ПК как «свободный». `CORP\\login` и `login@domain` из буфера обмена понимаются. Режимы «архивы» (все ПК, за которыми сидел пользователь) и «отключённые учётки». |
| **Принтеры** | В инспекторе — кликабельные бейджи принтеров ПК: 🌐 сетевой (с IP), 🔗 общий (`\\\\server\\queue`), 🔌 USB, ★ по умолчанию. Виртуальные (Microsoft PDF/XPS, OneNote, факс, PDF-принтеры) отфильтрованы. Клик (или просто ввод IP/модели в поиск) → строка **самого принтера** с доступностью (TCP 9100/631/80, затем ping); **кто подключён** — в статусе и в инспекторе принтера (режим `printer: …` показывает и владельцев); инспектор принтера: адрес, «Пинг», «Веб-панель», строка «Проверка» (при поиске по IP: порты печати / веб-панель → действительно принтер; 445/3389 → это компьютер; молчит → не проверено), таблица ПК; столбцы «Телефон»/«IP-тел» в режиме принтера скрыты. Диалог «🖨️ Принтеры парка» (`Ctrl+Shift+P`): сводка модель/тип/IP/число ПК с фильтрами и CSV. Данные — из инвентарных CSV, индексируются сканером. |
| **Инспектор** | Правая панель: ФИО, должность, ПК + IP, статус сети с живым пингом, телефоны, адрес/кабинет, последний вход, принтеры, характеристики ПК. Строка **«Учётная запись»**: блокировка (lockout), срок пароля («истекает через 5 дн.» / «ИСТЁК»), истечение УЗ, число неудачных входов — красным, если что-то требует внимания. Кнопка «Копировать» формирует готовую карточку для чата. |
| **Дашборд** | Плитки «в сети / не в сети / всего в AD» с drill-down в список ПК; история поисков; быстрый доступ. |
| **Действия с ПК** | RMS, **«Диск»** (один том → `C$`, несколько → меню выбора тома, 3.2.9), `compmgmt.msc`, перезагрузка/выключение (с подтверждением и записью в журнал). |
| **Карточка AD** (3.2.5) | Шапка с инициалами, полным ФИО и бейджем состояния; действия только про учётку: **смена пароля** (одно окно: пароль крупно, длина 10/12/16 или свой, «сменить при входе», снятие блокировки, карточка для сотрудника), снять блокировку, отключить/включить УЗ. Вкладки: **Профиль** (поля в две колонки, отправляются только изменённые; смарт-карта, Lync), **Группы** (две панели рядом, фильтр, участники), **Учётная запись** (состояние с причиной, пароль, блокировка, срок, неудачные входы, последний вход, DN), **Характеристики ПК** (только чтение + привязка ПК). Действия с ПК — в инспекторе. |
| **Регистрация** | Мастер из 4 шагов с живым предпросмотром учётки и чек-листом готовности; генерация логина/пароля, подсказки из AD, «как у сотрудника», безопасная последовательность создания (add → пароль → enable, откат при сбое). |
| **Инвентарь** | Фоновый сканер парка (AD → DNS → ping → журналы входов, PowerShell RunspacePool ×50). |
| **Excel-опись** (3.2.2) | Организация с фильтром → предпросмотр таблицы и плитки (сотрудников / с ПК / без ПК / в сети / версий ОС) → 14 колонок галочками → XLSX с титулом, закреплённой шапкой, автофильтром, подсветкой «Не привязан» и листом «Сводка». |
| **Свободный IP** (3.2.2) | Карта подсети — широкая матрица 32×8 (3.2.9): свободен · в инвентаре · аренда/резерв DHCP · ping · PTR; клик задаёт старт. Найденный адрес крупно с чек-бейджами и вердиктом DHCP (`[Scanner] dhcp_servers`), «Копировать / Пинг / Следующий», таблица находок сеанса. |
| **Пинг** (3.2.1–3.2.7) | Монитор доступности: индикатор состояния (офлайн-ПК — сразу «Узел не отвечает», 100 % потерь), график отклика на 60 замеров с маркером «⏳ ждём ответ» на таймаутах, потери/мин/сред/макс/джиттер и единая лента журнала — каждый ответ ping структурированно (№, время, результат, отклик, TTL), события выделены, фильтр «Все / Сбои и события / События» (окно всегда открывается на «События», консольный текст — по чипу «Все»); пауза, сброс, «Копировать отчёт» и «Копировать вывод ping» (привычный консольный текст). |
| **Здоровье ПК → Ошибки** (3.2.1) | Журнал Windows System/Application: фильтр по пяти уровням, период «с … по», таблица событий; счётчики «критических / ошибок / предупреждений» и топ источников считаются ровно по показанным событиям (3.2.9). |
| **Столбцы таблицы** | ПКМ по заголовку: простой список галочками + «↺ Стандартный набор». По умолчанию: Логин · ФИО · Учётка (только **Активна** / **Не активна**; причина — в инспекторе) · Имя ПК · Сеть · Телефон · IP-тел; остальные включаются галочкой. Ширина столбцов во всех таблицах подгоняется под текст (длинное — переносится). |

## ⚡ Производительность

- Сопоставление «пользователь → ПК» через обратный индекс (было O(записей × ПК)): 30 000 ПК × 300 записей — ~0,1 с вместо ~0,8 с.
- DNS/ping результаты кэшируются 20 с: при наборе «ива → иван → иванов» одни и те же ПК не опрашиваются трижды.
- Индексы SQLite на `pc_inventory(current_user, ip_address)`, `pc_printers(name, ip_address)`, `audit_cache(login)`, `audit_log(ts)`.
- Пинг до 50 ПК параллельно (TCP/445 → ICMP); LDAP с `paged_search` и жёстким лимитом выдачи.

## 🔒 Безопасность

- **Пароль не хранится открытым текстом**: DPAPI на Windows, `keyring` на других ОС, файл — в профиле пользователя.
- **LDAPS по умолчанию** с проверкой сертификата; операции с паролем без TLS блокируются с понятным сообщением.
- Все LDAP-выборки **постраничные** (обход лимита 1000 записей AD).
- Пользовательский ввод экранируется: `escape_filter_chars` для LDAP, `ESCAPE` для SQL `LIKE`, валидация имени узла перед `shutdown`/`ping`/PowerShell, `html.escape` в rich-text.
- Журнал действий администратора (`audit_log`) с UI просмотра и экспортом; логи приложения — `Documents/ADK/adk.log` с ротацией (5 × 2 МБ).
- Сброс пароля — только по LDAPS; новый пароль не пишется ни в лог, ни в журнал (в `audit_log` попадает лишь факт и режим).
- Нет жёстко прописанных доменов/путей — всё в `config.ini`.

## 🛡️ Сохранность данных (БД и инвентарные CSV)
- **CSV сканера открываются только на чтение** — ADK их не переписывает и не удаляет. Диагностика (S.M.A.R.T., карта диска, журнал ошибок, DHCP, живой опрос принтеров, пинг) — тоже только чтение; это закреплено тестом.
- В SQLite пишут только `db.py` и `software.py` через одно соединение с `busy_timeout` и повтором при блокировке.
- Перед первой миграцией схемы после обновления делается копия `pc_mapping.db.bak-…` (3 последние хранятся); `db.quick_check()` проверяет целостность файла.
- Живой опрос принтера и любой «просмотр как сейчас» никогда не обновляют кэш инвентаря — снимок меняется только сканером.
