## ✅ Что нужно

| | Минимум | Зачем |
|---|---|---|
| ОС | Windows 10/11 или Windows Server 2016+, компьютер **в домене** | сканер парка, опрос ПК (WinRM/WMI), пинг, DHCP, хоткей работают только на Windows |
| Учётная запись | доменная; для действий с ПК — администратор на этих ПК; для изменений в AD — соответствующие права в домене | ADK ничего не делает от своего имени — всё под вашей учёткой |
| Сеть | доступ к контроллеру домена по LDAP (порт 389) или LDAPS (636); к ПК — 445 (SMB), 135 (RPC/WMI), 5985 (WinRM) | см. [«если что-то не работает»](#-если-что-то-не-работает) |
| Python | **3.11 или 3.12** (только для запуска из исходников и сборки exe) | для готового `ADK.exe` Python не нужен |

### Зависимости Python

Все ставятся одной командой `pip install -r requirements.txt`. Что это и зачем:

| Пакет | Роль |
|---|---|
| `PyQt6` | интерфейс |
| `ldap3`, `pyasn1` | работа с Active Directory по LDAP |
| `pywin32` | шифрование сохранённого пароля (Windows DPAPI), COM |
| `winkerberos` | вход без пароля (SSO / Kerberos) |
| `cryptography` | привязка канала для Kerberos поверх LDAPS |
| `keyring` | хранилище пароля на не-Windows (для разработки) |
| `openpyxl` | Excel-опись |

Для разработки и тестов дополнительно `requirements-dev.txt`: `pytest`, `pyflakes`, `pillow` (GIF для документации).
Для сборки exe — `pyinstaller` (ставит `build_exe.bat`).

## 🚀 Вариант А — готовый `ADK.exe` (без Python)

1. Откройте [**Releases**](https://github.com/AgentSharik/ADK/releases) и скачайте `ADK-<версия>-win64.zip`.
2. Распакуйте в любую папку — например `C:\Program Files\ADK` или на сетевой диск. Внутри: `ADK.exe` и папка `_internal` (библиотеки Qt). **Они должны лежать рядом**, отдельно exe не работает.
3. Запустите `ADK.exe`. Первый запуск создаст `%USERPROFILE%\Documents\ADK\config.ini` и спросит, **где лежит или будет лежать база** (см. ниже), затем покажет окно входа.
4. Заполните `config.ini` — см. [настройка](#-настройка-configini) — и запустите снова.

Ярлык — на `ADK.exe`. Обновление — заменить содержимое папки; конфиг, база и лог лежат в `Documents\ADK` и не трогаются.

### 🗄️ Первый запуск: где база

База ADK — один файл `pc_mapping.db` (инвентарь парка, история, заметки, принтеры). При первом запуске, ещё до окна входа, ADK спрашивает папку для него:

- **База уже есть** (в этой папке лежит `pc_mapping.db` с данными) — ADK просто начинает с ней работать. Так подключают второй ПК к уже настроенному ADK.
- **Базы нет** — файл создаётся, а сразу после входа запускается **первичное наполнение**: сканер парка (все ПК из домена, их IP, кто за ними работает, последний вход) и живой опрос принтеров со всех ПК в сети. Прогресс виден в строке состояния, кнопка «⏹ Остановить наполнение» рядом; дальше сканер обновляет базу сам по расписанию (`[Scanner] auto_scan_interval_min`).

Вопрос задаётся один раз — ответ сохраняется в `config.ini` (`[Paths] db_path`, `db_ready = true`). Чтобы задать его снова, удалите строку `db_ready`.

> 💡 **Рекомендация.** Установите ADK на **одном** компьютере (или на сетевой папке), а остальным сотрудникам дайте **ярлык на этот `ADK.exe`**. Тогда база одна, инвентарь и заметки общие, а наполнять её нужно один раз. Если каждый распакует свою копию и ответит «в моих документах» — у каждого будет своя база, и данные разойдутся. Для отдела ADK и базу кладут на сервер — см. [серверный режим](#-серверный-режим-и-cli).

### 🛡️ Как ADK бережёт базу (3.6.0)

- **Обычный режим журнала.** База ведётся в обычном режиме SQLite — он единственный работает через сетевые папки, поэтому базу можно держать на сервере и запускать ADK ярлыком с других ПК. Ускоренный режим (WAL) рассчитан только на локальный диск, ADK его не использует и не включайте его вручную; базы, созданные версиями 3.5.4–3.5.11, при первом запуске 3.6.0 переводятся в обычный режим автоматически.
- **Сторож зависшего запроса.** Если запрос к базе идёт дольше **минуты**, ADK прерывает его, показывает окно «Соединение с базой признано зависшим» (что делать — прямо в окне) и закрывается. Ожидание занятой базы — 10 с на попытку, 3 попытки, а не минуты, как раньше.
- **Резервные копии.** Каждые 6 часов (`[Paths] backup_every_hours`, 0 — выключить) в папку `backups` рядом с базой кладётся согласованная копия `pc_mapping-ГГГГММДД-ЧЧММСС.db`; хранится 12 последних (`backup_keep`). Копия делается и при старте ADK, если последняя старше 6 часов. Восстановить — закрыть все ADK, заменить `pc_mapping.db` копией.
- **Один сканер на общую базу.** Если базу открыли несколько ADK, парк сканирует только тот, кто первым взял «аренду» (20 минут, продлевается), остальные видят «парк сканирует ПК X» и не пишут в базу одновременно.

### ⚠️ Предупреждения Windows при первом запуске

- **SmartScreen «Неизвестный издатель» / «Windows защитила ваш компьютер».** Это не ошибка, а отметка, что `ADK.exe` не подписан сертификатом издателя. Бесплатно её убрать нельзя: нужен либо купленный сертификат подписи кода (OV/EV, выдают удостоверяющие центры, стоимость — ежегодная), либо сертификат из корпоративного ЦС (Active Directory Certificate Services), которому доверяют все ПК домена. Подписывается одной командой из Windows SDK: `signtool sign /a /fd SHA256 /tr http://timestamp.digicert.com /td SHA256 ADK.exe`. Без подписи — «Подробнее → Выполнить в любом случае» один раз; для отдела можно раздать разрешение групповой политикой (AppLocker / правило по хешу).
- **Антивирус помечает `ADK.exe` как подозрительный.** Программы, собранные PyInstaller (Python, упакованный в exe), антивирусы иногда считают подозрительными «по внешности»: внутри распаковывается интерпретатор, exe не подписан, а такой же упаковщик встречается и во вредоносных файлах. Сама программа ничего плохого не делает — исходники открыты, а сборка идёт на GitHub из них же. Что мы уже сделали, чтобы срабатываний было меньше: сборка **без UPX** (сжатие, которое антивирусы не любят) и **в папку**, а не в один файл (тогда ничего не распаковывается во временную папку при каждом запуске). Что сделать, если антивирус всё же ругается: добавить папку с ADK в исключения на ПК администраторов; отправить файл вендору антивируса как ложное срабатывание (обычно снимают за 1–2 дня); подписать exe сертификатом (см. выше) — у подписанных файлов срабатываний почти нет.

## 🐍 Вариант Б — из исходников (Python)

### 1. Установить Python

Скачайте Python 3.12 с [python.org](https://www.python.org/downloads/windows/) и при установке **поставьте галочку «Add python.exe to PATH»**. Проверка в консоли:

```bat
python --version
```

### 2. Получить код

```bat
git clone https://github.com/AgentSharik/ADK.git
cd ADK
```

Без git — на GitHub «Code → Download ZIP», распаковать, открыть консоль в этой папке.

### 3. Создать окружение и поставить зависимости

```bat
python -m venv .venv
.venv\Scripts\activate
python -m pip install --upgrade pip
pip install -r requirements.txt
```

`.venv` — отдельная папка с библиотеками только для ADK, системный Python остаётся чистым. Активировать окружение (`.venv\Scripts\activate`) нужно в каждой новой консоли перед запуском.

### 4. Запустить

```bat
python run.py
```

(или `python -m adk`). Первый запуск создаёт `Documents\ADK\config.ini` и спрашивает, [где база](#️-первый-запуск-где-база) — заполните конфиг ([ниже](#-настройка-configini)) и запустите снова.

### Рекомендация: PyCharm

Для правки конфигов, плагинов и самого кода удобно использовать [PyCharm Community](https://www.jetbrains.com/pycharm/download/) (бесплатный): подсветка, автодополнение, встроенный терминал и запуск тестов кнопкой.

1. File → Open → папка `ADK`.
2. PyCharm предложит создать окружение из `requirements.txt` — согласитесь (или укажите уже созданный `.venv`).
3. В репозитории лежат готовые конфигурации запуска (`.run/`): **ADK** — запуск программы, **Tests (pytest)** — тесты. Они появятся в списке справа вверху.

## 🔨 Сборка своего `ADK.exe`

Нужен Python 3.11/3.12 в PATH. В папке проекта:

```bat
build_exe.bat
```

Скрипт сам создаст `.venv`, поставит зависимости и PyInstaller, проверит импорт и соберёт программу.
Результат — **папка `dist\`**, в ней `ADK.exe` и `_internal\`. Копируйте `dist` целиком (можно переименовать), ярлык — на exe.

Параметры сборки — в `adk.spec`: onedir (быстрый старт, меньше ложных срабатываний антивируса, чем onefile), без консольного окна, иконка `assets\icon.ico`, версия из `version_info.txt`.

Та же сборка выполняется автоматически на GitHub (`.github/workflows/build-exe.yml`): при публикации тега `vX.Y.Z` архив `ADK-X.Y.Z-win64.zip` прикладывается к Release.

## ⚙️ Настройка `config.ini`

Файл: `%USERPROFILE%\Documents\ADK\config.ini` (образец со всеми ключами и комментариями — `config.example.ini` в репозитории). Кодировка UTF-8. Ниже — то, без чего программа не заработает, и то, что чаще всего меняют.

### `[AD]` — домен

При первом запуске на доменном компьютере ADK **сам определяет** `domain_netbios`, `dc_host`, `search_base`, `upn_suffix` (спрашивает у Windows, к какому домену и контроллеру подключён компьютер) и записывает их в `config.ini`. Проверьте — обычно менять нужно только `users_ou` и, возможно, `use_ssl`.

```ini
[AD]
domain_netbios = CORP
dc_host = dc01.corp.example.local
search_base = DC=corp,DC=example,DC=local
users_ou = OU=Сотрудники,DC=corp,DC=example,DC=local
upn_suffix = corp.example.local
use_ssl = false
tls_validate = false
connect_timeout = 5
max_password_age_days = 90
```

Где взять значения — всё видно из консоли на любом доменном ПК:

| Ключ | Что это | Как узнать |
|---|---|---|
| `domain_netbios` | короткое имя домена (то, что перед `\` в логине `CORP\ivanov`) | `echo %USERDOMAIN%` |
| `dc_host` | имя контроллера домена | `echo %LOGONSERVER%` (без `\\`) + `.` + `echo %USERDNSDOMAIN%`; или `nltest /dsgetdc:%USERDNSDOMAIN%`. Можно указать и просто имя домена (`corp.example.local`) — DNS сам выберет контроллер |
| `search_base` | корень каталога, откуда ищутся пользователи и ПК | из DNS-имени домена: `corp.example.local` → `DC=corp,DC=example,DC=local` |
| `users_ou` | подразделение (OU), куда создаются новые пользователи | «Active Directory — пользователи и компьютеры» → правый клик по нужной OU → Свойства → вкладка «Редактор атрибутов» → `distinguishedName`. Или PowerShell: `Get-ADOrganizationalUnit -Filter * \| Select Name, DistinguishedName` |
| `upn_suffix` | суффикс логина вида `ivanov@corp.example.local` | `echo %USERDNSDOMAIN%` |

**`use_ssl` и `tls_validate` — как выбрать.**

- `use_ssl = true` → ADK подключается к контроллеру по **LDAPS, порт 636**; `false` → по **обычному LDAP, порт 389**.
- `tls_validate` работает только при `use_ssl = true`: `true` — сертификат контроллера должен быть доверенным (выдан вашим центром сертификации); `false` — принимается любой, в том числе самоподписанный.

Проверить, слушает ли контроллер 636, можно одной командой:

```powershell
Test-NetConnection dc01.corp.example.local -Port 636
```

Если `TcpTestSucceeded : False` — LDAPS на контроллере не включён (по умолчанию Windows Server его не поднимает, нужен сертификат для контроллера домена). В этом случае ставьте `use_ssl = false` — ADK будет работать по 389: поиск, карточки, группы, блокировки, включение/отключение учёток, всё про ПК. Когда LDAPS появится (обычно — после развёртывания центра сертификации AD CS, контроллер получает сертификат сам), переведите `use_ssl = true`; `tls_validate = false` — только если сертификат самоподписанный.

С `use_ssl = true` и закрытым 636 программа сообщит «контроллер домена недоступен» — это не про сеть, а именно про порт 636.

### `[Paths]` — где данные

```ini
[Paths]
db_path = %USERPROFILE%\Documents\ADK\pc_mapping.db
invent_hardware_dir = \\fileserver\invent$\comp\hardware
invent_comp_dir = \\fileserver\invent$\comp
invent_compexit_dir = \\fileserver\invent$\compexit
pst_backup_base =
rms_viewer_path = C:\Program Files (x86)\Remote Manipulator System - Viewer\rutview.exe
```

- `db_path` — база ADK (SQLite): инвентарь парка, история, заметки, кэш ПО и принтеров. Выбирается при первом запуске (`db_ready = true` — вопрос уже задан). Один ADK на отдел + ярлыки у коллег = одна база; сканер по расписанию на сервере — [серверный режим](#-серверный-режим-и-cli).
- `invent_*_dir` — папки с инвентарными CSV (если у вас есть logon-скрипт, который их складывает). Если их нет — оставьте как есть: принтеры и ПО собираются живым опросом ПК («📡 Опросить парк»), инвентарь — встроенным сканером.
- `pst_backup_base` — пусто = не экспортировать почту при увольнении.
- `rms_viewer_path` — путь к RMS Viewer для кнопки «Подключиться».

### `[Scanner]` — какие ПК считать парком

```ini
[Scanner]
auto_scan_interval_min = 30
host_pattern = ^(WS-\d+|PC-.*)$
host_exclude = (VIRT|VM|VBOX|TEST|SRV|SQL|SERVER)
valid_subnets = 10.,192.168.,172.
dhcp_servers =
```

`host_pattern` — регулярное выражение по именам компьютеров из AD: только они попадают на дашборд и в сканер. Посмотрите, как у вас называются рабочие станции (`Get-ADComputer -Filter * | Select -First 20 Name`), и опишите шаблон. `dhcp_servers` — имена DHCP-серверов через запятую для сверки в «Свободном IP»; пусто — сверка не выполняется и элементы DHCP в окне не показываются.

### `[Access]` — кто что может

См. [роли](#-роли). По умолчанию все списки пусты — права есть у всех, кто вошёл; настоящая граница — права вашей учётки в домене.

### Остальное

`[UI]` — язык, трей, глобальная клавиша вызова; `[Design]` — пишется диалогом «Дизайн»; `[Notify]` — почта об изменениях (пусто = выключено); `[Attention]` — пороги сводки «Внимание»; `[Plugins]` — папка плагинов; `[Updates]` — файл с номером новой версии на сетевом диске для баннера обновления.

## 🔑 Первый вход и проверка

1. Запустите ADK, в окне входа — доменный логин и пароль (`ivanov` или `CORP\ivanov`). «Запомнить» хранит пароль зашифрованным (DPAPI) — прочитать его может только ваша учётка на этом ПК.
2. Вход без пароля (SSO по Kerberos) работает, если контроллер доступен по LDAPS (`use_ssl = true`); по 389 контроллер такой вход не принимает — введите пароль.
3. После входа ADK покажет, какая роль определена по вашим группам. Введите в поиск свою фамилию — должна появиться карточка. Через 1–2 минуты первый проход сканера заполнит дашборд.
4. Лог — `Documents\ADK\adk.log`. Если что-то не работает, причина почти всегда там или в тексте ошибки в окне.

## 🗄️ Серверный режим и CLI

База ADK — **один файл SQLite**, других движков нет (3.6.1: PostgreSQL-адаптер удалён — один способ хранения, одна инструкция, меньше непроверенного кода). Один администратор — база в `Documents\ADK`. Отдел — так:

1. Распакуйте ADK на сервер (или один всегда включённый ПК), при первом запуске укажите папку для базы на нём же — например `D:\ADK\pc_mapping.db`.
2. Остальным сотрудникам дайте ярлык на `\\server\ADK\ADK.exe` (или на локальную копию exe с той же папкой базы в `config.ini`). Все работают с одной базой; парк сканирует только один экземпляр (аренда 20 минут), остальные читают.
3. Если ADK на сервере никто не держит открытым — сканер можно запускать по расписанию без окна: планировщик Windows → `ADK.exe --serve 30` (скан каждые 30 мин + письма по сводке «Внимание»).

Резервные копии — папка `backups` рядом с базой (каждые 6 ч); перенос на другой сервер = скопировать `pc_mapping.db` и поправить `db_path`.

CLI:

```bat
adk --find иванов                 ; таблица в консоль (код возврата 1, если пусто)
adk --find 10.0.2 --json          ; JSON для скриптов
adk --export-inventory парк.xlsx
adk --attention                   ; сводка «Внимание»
adk --ping WS-101 WS-105 --json
adk --wol WS-133                  ; по сохранённому MAC
adk --scan                        ; один проход сканера
```

Учётные данные — сохранённые (Windows DPAPI: `win32crypt` или `ctypes`+crypt32; иначе keyring) или `ADK_USER` / `ADK_PASSWORD`.
Сохранённый пароль забывается только при ошибке учётных данных, а не при недоступном контроллере.

## 🔒 Роли

Изменяющие действия делятся на два класса, и у каждого — свой список групп AD:

| Право | Что открывает | Ключ `[Access]` |
|---|---|---|
| **ПК** | перезагрузка/выключение, WoL, опрос ПО, заметки, привязка ПК, «отложить» в сводке, изменяющие плагины | `pc_admin_groups` |
| **AD** | атрибуты, включение/отключение УЗ, снятие блокировки, сброс пароля, смарт-карта, создание пользователя, группы (в т. ч. массово и «Группы как у…»), шаблоны | `ad_admin_groups` |

Просмотр, поиск, пинг, здоровье ПК, входы, сравнения, экспорт, журнал — доступны всем всегда.

```ini
[Access]
pc_admin_groups = GT_Admins, IT-Admins   ; GT_Admins в AD только читает — но ПК обслуживает полностью
ad_admin_groups = IT-Admins              ; менять объекты домена могут только они
readonly_group = ADK-ReadOnly            ; члены — ни ПК, ни AD
admin_groups =                           ; совместимость: оба права сразу
```

Пустой список — право есть у всех. Членство администратора (`memberOf`) читается из AD в фоне после входа.
Без права кнопки скрываются, а в карточке AD поля становятся только для чтения. Роли ADK — удобство и защита от случайного клика; настоящая граница — ACL домена: запись в LDAP идёт под учёткой администратора, и без прав контроллер вернёт `insufficientAccessRights`.

## 🧩 Плагины

Любой `*.py` в `[Plugins] dir` (по умолчанию `Documents\ADK\plugins`) с классом-наследником `adk.plugins.Action`
становится кнопкой в инспекторе и пунктом контекстного меню. Файлы с `_` в начале имени выключены
(так поставляется шаблон `_template_plugin.py`). Ошибка в плагине пишется в лог и не ломает остальные.

Кнопка **🧩 Плагины** в шапке открывает менеджер: список файлов, «Включить/Выключить», «Открыть файл», «Удалить», «Перечитать» (без перезапуска) и **«Создать шаблон плагина»** — файл со всей документацией внутри.

```python
from adk.plugins import Action

class UserProfile(Action):
    name, icon = "Профиль пользователя", "📂"
    needs_pc = True        # кнопка активна только для строк с ПК
    modifying = False      # True — скрывается в режиме «только чтение»

    def run(self, ctx):    # ctx: login, comp, ip, fio, admin, entry (ldap3), conn_factory
        import subprocess
        subprocess.Popen(["explorer", rf"\\{ctx['comp']}\C$\Users\{ctx['login']}"])
        return f"Открыт профиль {ctx['login']} на {ctx['comp']}"   # строка попадает в статус и журнал
```

## 🩹 Если что-то не работает

| Симптом | Причина и что сделать |
|---|---|
| «Контроллер домена недоступен» при `use_ssl = true` | порт 636 (LDAPS) на контроллере не открыт — проверьте `Test-NetConnection dc -Port 636`; поставьте `use_ssl = false` или включите LDAPS на контроллере |
| «Сертификат контроллера домена не доверен» | `tls_validate = false`, либо добавьте корневой сертификат вашего ЦС в доверенные |
| «Неверный логин или пароль», хотя пароль верный | логин без домена и неверный `domain_netbios`; попробуйте `CORP\ivanov` |
| Поиск ничего не находит | неверный `search_base` — пользователи лежат вне указанного корня; укажите корень домена `DC=…` |
| Дашборд пустой, «0 рабочих станций» | `host_pattern` не совпадает с именами ваших ПК — проверьте `Get-ADComputer` и поправьте шаблон |
| «Здоровье ПК», «ПО», «Входы за 24 ч» — ошибка с упоминанием WinRM/RPC | на ПК не включён WinRM (`winrm quickconfig` или групповая политика) и/или закрыт 135 (правила брандмауэра «Инструментарий управления Windows»); нужна учётка с правами администратора на этом ПК |
| «database is locked» | базу держит другой процесс дольше 10 с: зависший экземпляр ADK, антивирус на лету, резервное копирование файла. Закройте лишние ADK; папку базы добавьте в исключения антивируса. Если ADK показал окно «Соединение с базой признано зависшим» — следуйте его подсказкам, копии лежат в `backups` рядом с базой |
| ПК есть в AD, но «Не в сети» всегда | ПК не отвечает на 445 и ICMP — проверьте брандмауэр на ПК; `valid_subnets` должен включать его подсеть |
